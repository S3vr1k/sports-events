## Стили в Word и LibreOffice

Стили доступны в панели стилей. Для нового абзаца можно выбрать нужный стиль или скопировать существующий образец вместе со знаком абзаца.

| Назначение | Стиль |
|---|---|
| Обычный абзац | Основной текст (также настроен Normal / Обычный) |
| Раздел с новой страницы | Заголовок 1 / Heading 1 |
| Подраздел | Заголовок 2 / Heading 2 |
| Более мелкий заголовок | Заголовок 3 / Heading 3 |
| Код и команды | Листинг |
| Подпись под изображением | Подпись рисунка |
| Название над таблицей | Название таблицы |
| Текст внутри таблицы | Текст таблицы |
| Запись источника | Библиография |

Основной текст: A4, Times New Roman 14, полуторный интервал, отступ первой строки 1,25 см; поля 3 см слева, 1,5 см справа, по 2 см сверху и снизу. Официальные первые два листа сохраняют оформление формы задания. Они учитываются в нумерации, но номер на них не показывается.

В документе есть автоматическое оглавление, закладки заголовков и поля последовательной нумерации рисунков, таблиц и листингов. После правок в Word выдели весь документ и обнови поля (Ctrl+A, F9; для оглавления выбери обновление целиком). В LibreOffice обнови оглавление через его контекстное меню. После изменения порядка рисунков проверь упоминания номеров в тексте: они обычные текстовые ссылки.

На этой CachyOS при проверке Times New Roman подменяется Liberation Serif, Courier New — Liberation Mono. В самом DOCX указаны требуемые Times New Roman и Courier New. Для совпадения с требованиями установи нужные шрифты либо проверь документ на компьютере, где они есть; затем обнови оглавление и проверь страницы.

## Какие скриншоты вставить

Две схемы уже вставлены. Нужно заменить шесть абзацев с пометкой «Вставить скриншот». Подпись под каждым местом оставь. Изображение вставляй «в тексте», шириной примерно 15–16 см, с сохранением пропорций. Удали лишние пустые интервалы у заменяемого абзаца, если они остались. Не захватывай пароль или другие секреты; в заявках используй вымышленные ФИО.

- Рисунок 3. Состояние пяти сервисов после запуска: терминал с docker compose ps; все пять сервисов должны быть запущены.
- Рисунок 4. Таблицы и данные PostgreSQL в pgAdmin: дерево public → Tables и результат SELECT event, title, location FROM public.events; пароль в кадр не включать.
- Рисунок 5. Получение списка соревнований через обратный прокси: браузер localhost:8080/api/events с JSON и видимой адресной строкой.
- Рисунок 6. Главная страница школьного спортивного фестиваля: главная страница localhost:8080 в обычном масштабе браузера.
- Рисунок 7. Регистрация участника на выбранную дисциплину: форма registration.html с выбранной дисциплиной и сообщением об успешной тестовой регистрации.
- Рисунок 8. Список участников выбранного соревнования: страница event.html с описанием дисциплины и тестовой записью в списке.

Скрин с характеристиками ПК не обязателен: сведения об ОС, процессоре и памяти уже приведены текстом. Снимок удаления отдельной записи и ответы 404/422 можно добавить для более полного протокола, но для них пока нет отдельных мест.

## Что проверить перед сдачей

- Сверить ФИО, точную тему, руководителя, группу и даты на первых листах. Подписи и оценка оставлены пустыми.
- Добавить фактические версии Docker Engine и Compose из своей среды, а также идентификатор итогового коммита.
- Проверить, что db/init.sql и актуальная конфигурация добавлены в репозиторий. Локальные незакоммиченные файлы не попадут к проверяющему при клонировании.
- Дополнить результаты проверок 404, 422 и недоступности API фактическими наблюдениями.
- После реализации Swarm и CI/CD добавить подтверждения: список узлов, список сервисов стека, успешный запуск GitHub Actions и работающую версию после деплоя.
- Подготовить презентацию. После этого обновить статусы в приложении Б.
- Обновить поля, оглавление и проверить разрывы страниц после добавления изображений.
