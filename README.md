# Спортивный фестиваль школы № 2051

Учебный веб-проект для просмотра соревнований и регистрации участников школьного спортивного фестиваля.

Тема курсовой работы: **«Настройка и администрирование системы управления спортивными событиями с автоматической обработкой данных участников»**.

Автор: Севрюков Александр Геннадьевич, группа ИКБО-16-25.

Проект находится на стадии рабочего прототипа и не является официальным сайтом школы.

## Возможности

- Просмотр соревнований, их описания и места проведения.
- Регистрация участника на выбранную дисциплину.
- Общий список регистраций с поиском по имени и фильтром по дисциплине.
- Просмотр участников отдельного соревнования и карточки регистрации.
- Удаление регистрации с подтверждением.
- Хранение данных в PostgreSQL и администрирование через pgAdmin.

В начальном наполнении доступны бег на 3 километра, подтягивания, отжимания, гибкость и прыжки в длину. Шахматы показаны как планируемая дисциплина, регистрация на них пока закрыта.

Один человек может записаться на несколько дисциплин, заполнив форму для каждой. Каждая заявка хранится отдельной строкой с собственным идентификатором.

## Стек и сервисы

Система запускается через Docker Compose и состоит из пяти сервисов:

| Сервис | Технология | Назначение |
| --- | --- | --- |
| `fastapi` | Python 3.14.10, FastAPI, Psycopg 3 | API, проверка заявок и SQL-запросы |
| `db` | PostgreSQL 17.12 | Хранение соревнований и регистраций |
| `pgadmin` | pgAdmin 4, ветка 9 | Веб-интерфейс администрирования БД |
| `frontend` | Nginx 1.30.6, HTML, CSS, JavaScript | Выдача страниц и статических файлов |
| `proxy` | Nginx 1.30.6 | Единая точка входа и маршрутизация запросов |

Браузер обращается к `proxy` через порт `8080`. Запросы `/api/` передаются в FastAPI с удалением этого префикса, остальные — в `frontend`. Приложение и pgAdmin подключаются к PostgreSQL по имени сервиса `db` в сети Compose.

## Запуск

Нужны Git, работающий Docker Engine и команда `docker compose`. На macOS можно использовать Docker Desktop — перед запуском проекта он должен быть запущен. Устанавливать Python, PostgreSQL и Nginx отдельно на компьютер не требуется.

```bash
git clone https://github.com/S3vr1k/sports-events.git
cd sports-events
docker compose up -d --build
docker compose ps
```

При первом запуске дождитесь завершения инициализации PostgreSQL. Статус `Up` показывает, что контейнер запущен, но ещё не гарантирует готовность базы принимать запросы. Журнал можно посмотреть командой:

```bash
docker compose logs --tail=50 db fastapi
```

## Инициализация базы данных

В [db/init.sql](db/init.sql) сохранены структура таблиц и начальные данные: пять соревнований и три демонстрационные регистрации.

В БД используются две таблицы:

- `events` — код дисциплины, название, описание и место проведения;
- `participants` — идентификатор заявки, ФИО и ссылка на дисциплину.

При создании **пустого тома PostgreSQL** файл `init.sql` выполняется автоматически. Если том уже существует, повторный `docker compose up --build` не запускает инициализацию заново.

Git переносит файлы проекта и начальный дамп. Текущее содержимое тома БД между компьютерами через `git pull` не переносится.

### Если на другом компьютере нет таблиц

Все команды выполняются из корня проекта при запущенном сервисе `db`.

```bash
git pull
ls -l db/init.sql
docker compose exec db psql -U sevrik -d sports-events -c '\dt public.*'
```

Если проверка сообщает, что таблиц нет, загрузите дамп вручную:

```bash
docker compose exec -T db psql \
  -U sevrik -d sports-events \
  -v ON_ERROR_STOP=1 --single-transaction < db/init.sql
```

Команда остановится при первой ошибке и отменит импорт целиком. Она предназначена для пустой БД; если таблицы уже существуют, повторно выполнять этот импорт не нужно.

Проверка после загрузки:

```bash
docker compose exec db psql -U sevrik -d sports-events \
  -c 'SELECT count(*) FROM public.events;'
```

Сразу после загрузки начального дампа результат должен быть `5`. Обновите страницу сайта; в pgAdmin обновите узел `Tables` через контекстное меню.

## Подключение pgAdmin

1. Откройте [pgAdmin](http://localhost:5050). Для входа используйте значения `PGADMIN_DEFAULT_EMAIL` и `PGADMIN_DEFAULT_PASSWORD` из [docker-compose.yml](docker-compose.yml).
2. В дереве объектов выберите `Servers → Register → Server`.
3. На вкладке `General` задайте произвольное имя, например «Спортивный фестиваль».
4. На вкладке `Connection` укажите:

| Параметр | Значение |
| --- | --- |
| Host name/address | `db` |
| Port | `5432` |
| Maintenance database | `sports-events` |
| Username | `sevrik` |
| Password | Действующий пароль роли PostgreSQL |

При первой инициализации пароль роли задаётся через `POSTGRES_PASSWORD`; приложение использует тот же пароль в `DB_PASSWORD`. Пароль веб-интерфейса pgAdmin задаётся отдельно.

Изменение `POSTGRES_PASSWORD` в Compose **не меняет пароль уже существующей роли** в сохранённом томе. При ошибке `password authentication failed` проверьте параметры подключения и фактический пароль роли. Удаление сервера из дерева pgAdmin удаляет только сохранённое подключение, сохраняя БД и её таблицы.

После входа откройте `Databases → sports-events → Schemas → public → Tables`.

## API

В таблице приведены внутренние маршруты FastAPI. При обращении через порт `8080` перед ними добавляется `/api`: например, `/events` превращается в `/api/events`.

| Метод | Маршрут | Назначение |
| --- | --- | --- |
| `GET` | `/` | Служебное сообщение приложения |
| `GET` | `/events` | Список соревнований |
| `GET` | `/events/{discipline}` | Информация о дисциплине |
| `GET` | `/events/{discipline}/participants` | Регистрации на дисциплину |
| `GET` | `/participants` | Все регистрации |
| `GET` | `/participants/{participant_id}` | Одна регистрация |
| `POST` | `/events/{discipline}/register` | Создание регистрации |
| `DELETE` | `/participants/{participant_id}` | Удаление регистрации |

Параметр `discipline` принимает код из БД: `running`, `pullups`, `pushups`, `flexibility` или `jumps`. `participant_id` — целочисленный идентификатор заявки.

В текущем POST-обработчике ФИО передаётся параметром `name` **в строке запроса**, а не JSON-телом. Проверить операции можно в Swagger UI. Несуществующий объект возвращает `404`, некорректное имя или тип параметра — `422`. Успешные создание и удаление сейчас возвращают `200` и данные записи.

Проверка получения каталога через прокси:

```bash
curl http://localhost:8080/api/events
```

```text
└── app/
    ├── main.py              # Обработчики API и запросы к PostgreSQL
    ├── Dockerfile           # Образ FastAPI
    └── nginx/
        ├── Dockerfile       # Образ со статическими файлами
        ├── proxy.conf       # Конфигурация обратного прокси
        ├── index.html       # Главная страница
        ├── events.html      # Каталог соревнований
        ├── event.html       # Соревнование и его участники
        ├── participants.html
        ├── participant.html
        ├── registration.html
        ├── style.css
        ├── app.js
        └── assets/          # Изображение и сведения об источнике
```

Навигация между страницами выполняется HTML-ссылками. Общий `app.js` выбирает сценарий по атрибуту `data-page` элемента `body` и получает данные через `fetch`.

Ссылки на отдельные объекты содержат параметры: `event.html?discipline=running`, `participant.html?id=1`. Параметр `registration.html?discipline=running` заранее выбирает соревнование в форме.

## Обновление и диагностика

После изменения HTML, CSS или JavaScript пересоберите frontend:

```bash
docker compose up -d --build frontend
```

Если после пересоздания frontend прокси отвечает `502`, перезапустите его, чтобы обновить подключения к внутреннему серверу:

```bash
docker compose restart proxy
```

После изменения серверного кода пересоберите FastAPI:

```bash
docker compose up -d --build fastapi
```

Для просмотра состояния и журналов:

```bash
docker compose ps
docker compose logs --tail=100 fastapi db proxy
```

Если появляется `relation "events" does not exist`, проверьте таблицы и выполните импорт для пустой БД по инструкции выше. При старой версии страницы после пересборки обновите её с очисткой кэша браузера.

## Сохранение данных

Данные PostgreSQL находятся в именованном томе `postgres_data`, настройки pgAdmin — в `pgadmin_data`.

Для обычной остановки:

```bash
docker compose down
```

Команда сохраняет именованные тома. Параметр `-v` дополнительно удаляет их вместе с данными, поэтому для обычного завершения работы он не нужен.

Для создания актуальной SQL-копии:

```bash
mkdir -p backups
docker compose exec -T db pg_dump \
  -U sevrik -d sports-events --no-owner --no-acl \
  > backups/sports-events.sql
```

Файл `db/init.sql` — начальный снимок, он не обновляется автоматически после новых регистраций. Для переноса актуальных данных создайте отдельную резервную копию. Проверять её восстановление следует в отдельной пустой базе, чтобы сохранить рабочие записи.
